# Security policy

## Supported versions

Security fixes are provided for the latest tagged release only while the project remains actively maintained.

## Report a vulnerability

Do not open a public issue containing exploit details, credentials, or client information. Use GitHub's private vulnerability reporting feature on this repository. Include the affected version, impact, reproduction steps using fictional data, and any proposed mitigation.

Do not test against an installation you do not own or have explicit permission to assess.

## Operator responsibilities

This is self-hosted software, not a managed security service. Operators must provide HTTPS, host and database hardening, MFA or equivalent access controls, encrypted backups, monitoring, patching, malware controls, and an appropriate retention/deletion policy. See `docs/SECURITY_MODEL.md`.
